Arisk V2 sends real-time HTTP POST requests via Webhooks to your configured server to notify you of risk level changes or risk transactions for monitored addresses.

## Security Verification

To ensure the authenticity and integrity of the messages, every Webhook request sent by Arisk includes a digital signature. We strongly recommend verifying the request before processing.

### HTTP Headers

Each Webhook request contains the following key headers:

| Header | Description | Example |
| :--- | :--- | :--- |
| **X-Arisk-Signature** | RSA-PSS digital signature (Base64 encoded) | `aGVsbG8gd29ybGQ=...` |
| **Authorization** | Bearer Token (only if `auth_key` is configured) | `Bearer your-secret-token` |

### Verification Steps

1.  **Verify Signature (Required)**
    *   **Algorithm**: RSA-PSS with SHA-256
    *   **Signed Content**: Raw JSON string of the request body
    *   **Public Key**: Use the Arisk RSA public key below to verify the signature in `X-Arisk-Signature`.

2.  **Verify Authorization (Optional)**
    If you set an `auth_key` in the Webhook configuration, Arisk will add the following header:
    `Authorization: Bearer <your_auth_key>`

## Receive and process events

1. Retain the raw request body and verify its signature as described above. Do not verify against JSON that has been parsed and serialized again.
2. If `auth_key` is configured, check the `Authorization` value.
3. Identify the event by `type` and deduplicate using `alert.id`.
4. We recommend reliably storing the verified event or writing it to a durable queue before promptly returning HTTP `200`. The response body may be empty; the service does not parse it.
5. Run time-consuming business logic in the background. Do not treat messages that fail verification as valid events.

Network issues or retries can produce duplicate notifications. Both your receiver and background consumer should prevent repeated business effects for the same alert.
